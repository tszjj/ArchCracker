- 门禁：属于 W1 准出项

## 设计目标

解决「大字典一读就把内存吃满」的问题。此前把整个字典读入字符串、每行复制、全局去重，实际占用是文件大小的数倍，500 MB 文件可能吃几个 GB。面向真实的大字典场景，把 CLI 切到有界内存的流式候选源：内存只保留解码块、当前行、当前批次和候选水位位图不随文件大小增长。

## 实现要点

- **内存上限**：64 KiB 解码块 + 当前未完成行（≤1 MiB）+ 当前批次（≤4096 候选、≤8 MiB 字节）+ 每候选 1 bit 的连续水位位图（14.3M 候选约 1.8 MB）。
- **候选源**：只暴露「总数」和「下一批」两个方法；工作线程不再拿到整本字典，只处理当前批次；批次起始索引由源维护并校验连续性。
- **两遍读取**：先流式计数得到精确总数，再重新打开逐行产出；代价是启动多读一遍，换来进度百分比与续跑校验不需要特殊分支。
- **编码与行**：BOM 优先（UTF-8/UTF-16LE/BE），无 BOM 时前 64 KiB 按 UTF-8、否则 GBK；前段 ASCII 后段非法 UTF-8 的字典在计数报错后重扫为 GBK；空行跳过、行首尾空格保留；单行超 1 MiB 报错。
- **检查点**：水位仍是候选索引，按行顺序计数；续跑顺序跳到水位行并重新校验指纹，不存字节偏移；旧检查点若来自去重后的总数会被明确拒绝。

## 验收

- CLI 不再全量加载字典、不再深拷贝候选；
- 133 MB rockyou 实测进程常驻内存约 11 MB（候选 14,344,390，另含约 1.8 MB 水位位图）；
- 60k 字典 + 1.3 GB ZIP AES 命中 exit 0；
- UTF-8/BOM/UTF-16LE/BE/GBK、CRLF、空行、行首尾空格、前段 ASCII 后段 GBK 回退均通过；
- `--resume` 从水位继续；单行 1 MiB、批次 8 MiB 上限生效。

## 评审与对照意见

评审通过。已知取舍：启动多读一遍，大字典续跑还要顺序跳过，最坏 O(N)；水位位图是 O(N/8) 而非严格 O(1)（约 50M 行 6.3 MB、1B 行 125 MB）；流式默认不做全局去重，重复行会重复测试，以换取索引稳定和内存有界；计数与读取之间文件被修改时指纹只能发现首尾/大小/修改时间变化。

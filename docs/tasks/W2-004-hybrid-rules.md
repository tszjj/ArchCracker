## 设计目标

解决「用户有一本字典，想做常见变形却不想手写巨大字典文件」的问题。面向「公司名 + 两位数字」「首字母大写 + 常见后缀」这类真实场景，让用户用「字典 + 每条词的几种变形 + 固定或掩码前后缀」生成候选。候选由「字典中的一行」和「对该行施加的一个变换」共同决定，内核流式生成、不占满内存，并在启动前给出时间与空间估算。

## 1. 需求与功能对照

| 需求 | 功能 | 作用 |
|---|---|---|
| 处理超大字典 | 流式读取 | 避免整本字典进内存 |
| 一条命令表达多种变形 | 规则链 | 用户不为每种变形单独造字典 |
| 覆盖常见后缀组合 | 掩码前后缀 | 固定后缀只能试一个值，掩码能试一整段 |
| 恢复简单可靠 | 字典行为外层、变体为内层 | 断点只需记行号与变体索引 |
| 防止改了参数却从旧位置续跑 | 复合指纹 | 任一输入变化都拒绝旧断点 |
| 大组合能估算但拒绝不可执行 | 128 位估算、机器字长执行 | 与掩码/暴力决策一致 |
| 启动前知道成本 | 时间 + 空间估算 | 混合的位图会被变体数放大，最需要提前告警 |

## 2. 核心概念

候选由三层索引定位：全局索引 = 字典行号 × 每词变体数 + 变体索引。

- **字典行**：流式读取的非空行，原样保留首尾空格，行号即索引。
- **变体生成器**：规则链（对每行产生恰好 1 个候选）或前后缀掩码（产生前缀键空间 × 后缀键空间个候选，后缀变化最快）。
- **每词变体数 V** = 规则条数 + 前后缀键空间；两侧掩码合并为一个生成器，只给一侧时另一侧因子为 1，都不给则该生成器不存在。
- **总候选数** = 字典行数 × V。

字典放外层是因为字典行顺序读取，可以「读一行、生成该行所有变体、再读下一行」，内存里始终只有一行；反过来则需缓存整本字典或反复重读。

## 3. 规则语法

首版采用命名变换 + `|` 串联的可读语法，不做通用规则语言：

| 变换 | 作用（输入 `paSS`） |
|---|---|
| `identity` | 原样 `paSS` |
| `lower` / `upper` | 全小写 `pass` / 全大写 `PASS` |
| `capitalize` | 首字母大写、其余小写 `Pass` |
| `toggle` | 逐字符反转大小写 `PAss` |
| `reverse` | 字节反转 `SSap` |
| `append:<literal>` | 末尾追加，如 `append:123` → `paSS123` |
| `prepend:<literal>` | 开头前置，如 `prepend:x` → `xpaSS` |

大小写只处理 ASCII 字母，非 ASCII 字节原样保留；反转按字节进行，结果可能不是合法文本。字面量只允许 ASCII 可打印字符，`??` 转义一个字面 `?`，展开后 ≤64 字节；规则链 ≤8 段。每条 `--rule` 是独立变体生成器，按命令行顺序排列；不给规则时默认插入 `identity`。

前后缀掩码语法与掩码攻击一致，支持自定义字符集与 `??` 转义。候选 = 前缀 + 词 + 后缀，后缀变化最快；字典行 ≤1 MiB，每个掩码 ≤128 个位置。

例：`--rule identity --rule 'capitalize|append:123' --suffix-mask '?d?d'` 对字典行 `acme` 产出 `acme`、`Acme123`、`acme00`…`acme99`，共 102 个变体。

## 4. 生成与恢复

初始化：解析规则与掩码得到 V；扫描字典得到行数与最大行长度；计算总数，超过机器字长上限时只允许估算。

生成：批次内按变体索引产出候选——先依次应用规则链，再展开前后缀（后缀最快）；变体索引到 V 时读下一行。批次遵守 4096 在飞窗口与 8 MiB 字节上限，不整本缓存字典。

恢复：全局索引除以 V 得字典行号、取模得变体索引；顺序跳过到目标行；落在行边界时从该行变体 0 开始。用行号而非字节偏移，是因为字典编码可能是 UTF-8/GBK，字节偏移会漂移。

断点采用格式 v2，模式标记为混合，字典字段非空。签名为规则原文（含默认 `identity`）+ 前后缀原文 + 4 个自定义集原文，按固定顺序拼接后取 SHA-256；规则顺序变化视为不同攻击。字典文件变化由文件指纹覆盖。

## 5. CLI 与估算

参数：`-d`/`--dictionary`（必需）、`--rule`（可重复）、`--prefix-mask`、`--suffix-mask`、`--custom-charset1..4`、`--estimate`。与掩码/暴力模式互斥，必须给字典；不给任何规则或前后缀时提示改用字典模式。

时间估算沿用实测速率输出 ETA 与 24 小时容量；空间估算复用公共函数，位图按总数计算会被变体数放大——1400 万行字典 ×100 变体约 175 MB，超过 128 MB 阈值时警告。估算不含归档会话。

## 6. 验收与结果

规则变换、掩码前后缀、候选顺序、批次边界、断点全索引恢复、指纹拒绝、估算输出均有测试；`--estimate` 不启动攻击；超上限只估算并拒绝执行。

`cargo test --workspace` 144 core / 69 CLI（1 忽略）/ 2 FFI 通过；规则单测 7、混合单测 9、端到端 10。Windows x64 已验证；Linux/macOS 只保证 CI 编译与单测。

## 许可与评审意见

`sha2` 已是既有依赖，无新增许可登记；未链接或复制任何 RAR/7-Zip 源码，hashcat 未成为依赖，RAR 许可边界不变。评审通过。已知限制：位图随变体数放大（已告警，只警告不拒绝）；恢复需顺序跳行；规则是字节级，不覆盖 Unicode；不做通用规则引擎，无法表达「跳过前三个字符」等复杂变换；固定追加与固定后缀掩码功能重叠，推荐用前者，掩码用于产生多个候选。未做 1M×1GB 混合基准、7z/RAR 端到端与常驻内存实测。

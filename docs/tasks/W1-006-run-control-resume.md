## 设计目标

解决「长任务中途如何安全停下、停了之后如何接着跑」的问题。面向 1M 候选 / 1GB 归档这类耗时场景，让用户能暂停观察、优雅停止并保存进度，进程被强杀后也能从安全水位续跑而不漏候选。把暂停、停止、续跑建立在同一个可控状态机上，但保持三者语义可区分、可分别测试。

## 能力区分

| 能力 | 生命周期 | 是否落盘 | 恢复方式 |
|---|---|---|---|
| 暂停/继续 | 当前进程 | 不要求 | 清暂停标志，原地继续 |
| 停止 | 当前进程 | 可选（检查点） | 进程退出；无检查点则从头开始 |
| 断点续跑 | 跨进程 | 必须 | 新进程校验指纹后从水位继续 |

## 实现要点

- **运行状态**：`Running`、`Paused`、`Stopping`、`Stopped`、`Finished`；暂停时停止派发新批次，工作线程在当前候选边界停下并保留会话，继续时不重开归档。
- **连续完成水位**：记录「从 0 起连续完成的最远候选索引」而非「最大已尝试索引」，避免跳过仍在执行中的候选；命中候选本身不推进水位，保证命中后强杀仍会重放该候选。在飞候选窗口 ≤4096；强杀最多重放当前窗口。
- **外部引擎取消**：RAR 的 `UnRAR t` 是阻塞进程，停止时直接终止子进程并清理管道，不把「被取消」误判为密码错误。
- **检查点**：无 JSON 依赖的 key=value 格式，临时文件 + 落盘 + 改名保证原子写；包含归档/字典指纹（路径、大小、修改时间、首尾 CRC）、攻击参数与水位；`--resume` 校验指纹不匹配时明确拒绝，不静默从头跑。
- **CLI**：`--checkpoint`、`--resume`、TTY `p/r/s`、Ctrl+C 停止，退出码 0/1/2/3/4。

## 验收

- 暂停请求 ≤200 ms 被观察到、工作线程在候选边界停下；继续不重开会话；
- 优雅停止返回安全水位；强制停止走同一路径；外部取消有独立测试；
- 硬杀恢复不跳过候选（本机 2s kill：水位 11/200，续跑从 11 继续）；
- 归档/字典指纹不匹配拒绝续跑；命中结果先记录再停止；
- `cargo fmt`、`clippy -D warnings`、`cargo test --workspace`、MSRV 1.89、release、cargo-deny 全绿。

## 评审与对照意见

评审通过。已知边界：单次候选验证是阻塞调用，1GB 条目完整校验可能让「停止」超过 2 秒，验收口径为「控制请求 ≤200 ms 被观察、当前候选结束后停止」，不承诺抢占式中断；TTY 按键、RAR 停止矩阵、用户大语料与 MSVC CI 未自动化验证；暂停默认只在内存，关机/崩溃不可恢复。

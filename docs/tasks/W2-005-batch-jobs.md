## 设计目标

解决「一批相关归档要逐个手敲命令、一个坏包就丢掉全部结果」的问题。面向用户有 20 个加密包、怀疑用了同一批密码的场景，让用户一次提交清单，程序串行或有限并行跑完，单包失败不影响其他包，并在用户显式授权时把已命中密码复用给后续包。批量层只做编排，不碰候选生成与验证，未来界面队列可直接复用同一模型。

## 1. 需求与功能对照

| 需求 | 功能 | 作用 |
|---|---|---|
| 多包一次提交 | 任务清单 + batch 命令 | 不手敲多条命令，策略可复用 |
| 单包失败隔离 | 每任务独立状态机与错误码 | 一个坏包不丢已跑完的结果，也不阻断后续 |
| 每任务独立断点 | 按任务编号隔离断点文件 | 多任务共用文件会互相覆盖，复用现有格式可保留续跑 |
| 有限并行 | 全局并发上限（默认 1） | 每包都开满线程会超订，限流让行为可预测 |
| 包间密码复用 | 组内共享已命中密码，默认关闭 | 同组归档常共用密码，但复用需用户授权 |
| 不破坏候选索引 | 复用作为独立预阶段 | 混入候选源会改变索引与断点水位的对应关系 |
| 隐私 | 缓存只在内存、退出清空 | 防止明文密码落盘或被日志带出 |
| 启动前可预估 | 逐任务与汇总的 ETA/空间 | 用户需知道整批要跑多久、占多少内存 |

## 2. 模型

任务清单包含：任务列表、并发上限（默认 1）、是否启用复用（默认否）、断点根目录。每个任务包含：唯一编号、归档路径、攻击配置、线程数、是否复用（可单独关闭）。任务报告包含状态、命中密码（仅内存）、错误、耗时与断点路径。

状态流转：待运行 → 排队 → 运行中 → 命中 / 未找到 / 失败 / 已停止 / 已取消。

**已命中密码**：只收经归档引擎完整复核确认的密码，未经复核的候选与手工猜测都不进缓存。

**复用预阶段**：任务开始前先试缓存中的命中密码，命中则直接结束；未命中则照常进入正式攻击。该阶段不写断点、不占完成水位、不影响位图——这是最关键的设计约束，因为候选源的全局索引是续跑的唯一依据，插入长度可变的复用列表会改变索引与密码的对应关系。

## 3. 任务清单

首版用 TOML（可读性好、Rust 生态成熟），不引入多格式兼容层：

```toml
max_parallel = 2
reuse_found = false
checkpoint_root = "runs/2026-11-27"

[[jobs]]
id = "invoice-2024"
archive = "samples/invoice.zip"
threads = 4
mode = "dict"
dictionary = "dicts/common.txt"

[[jobs]]
id = "backup-a"
archive = "samples/backup.7z"
threads = 2
mode = "hybrid"
dictionary = "dicts/common.txt"
rules = ["identity", "capitalize|append:123"]
suffix_mask = "?d?d"
```

任务编号唯一、禁止路径分隔符，作为断点文件名；模式为字典/掩码/暴力/混合四选一，专属字段沿用各模式任务文档的语法；线程数与并发上限须通过启动校验。

**启动前全量校验**：清单语法、未知字段、重复编号、非法路径、非法模式参数、并发与线程超订——任一项失败即报错。这样可避免队列跑到一半才发现最后一个任务参数写错。

## 4. 与现有架构的关系

把单任务执行路径抽成内核函数 `run_attack(攻击配置, 运行选项) -> 任务报告`，单任务 CLI 与批量 CLI 共用，避免复制一份启动/停止/断点逻辑。

断点沿用格式 v2，只在路径上加任务编号隔离；续跑作用于单个任务，批量级恢复跳过已命中的任务，其余按各自断点续跑。

估算：串行整批 ETA 为各任务之和；有限并行按在飞任务数给出上界，不做未实测的线性外推；空间上界按并发数汇总，归档会话仍不纳入。提供只打印估算、不启动攻击的预演模式。

停止请求须传播到当前任务并保存其断点，已完成任务的结果保留。

## 5. CLI

`acx batch jobs.toml [--max-parallel N] [--reuse-found] [--fail-fast] [--dry-run]`

批量与单任务攻击参数互斥；命令行参数可覆盖清单同名字段；失败隔离是默认值，`--fail-fast` 开启后遇首个失败即停止后续。输出为逐任务状态摘要加末尾汇总。

批量退出码提案：按严重度取最高——停止 4 > 失败 3 > 校验错误 2 > 有命中 0 > 全未命中 1。单任务 CLI 的退出码语义不变。

命中密码只在标准输出与进程内缓存出现；日志、断点与清单不写明文密码；缓存退出即清空，无持久化文件。

## 6. 验收

- 清单解析覆盖四种模式；语法错误、重复编号、非法路径、非法参数均报错且不启动任何任务；
- 默认串行、并发上限生效；预演模式不启动攻击、不写断点；
- 三任务（命中/未命中/坏归档）验证失败隔离与汇总统计，坏包不阻断后续；
- 每任务断点互不覆盖，续跑只影响指定任务；
- 复用开关、单任务关闭复用、只复用已复核命中、退出后缓存不可恢复；
- 启动前逐任务与汇总估算；停止传播并保存断点；
- `cargo fmt`、`clippy -D warnings`、`cargo test --workspace` 通过，新增内核单测与 CLI 端到端测试；跨平台影响已说明（Windows 验证、其他未验证）。

## 7. 实现记录（2026-11-27）

- **模型**：`acx-core::job` 提供共用的 `run_job` / `estimate_job` / `validate_job`；单任务 CLI 与批量 CLI 走同一条执行路径（preflight、候选源、断点、调度、停止、报告），没有复制启动逻辑。
- **清单**：`acx-core::batch` 用 `serde` + `toml` 解析，`deny_unknown_fields`；相对路径按清单目录解析；校验唯一 ID、Windows 保留名/路径分隔符、四种模式的专属字段、线程 1..=256、`max_parallel × 最大任务线程 ≤ 256`。
- **运行**：每任务独立断点 `<checkpoint_root>/<id>.acx-checkpoint`；已存在则自动续跑；任务失败只影响该任务；`--fail-fast` 只停止调度新任务，已运行任务正常收尾。
- **并行**：固定大小 worker 池，按清单顺序取任务，结果按清单顺序汇总；线程预算启动前校验，超过可用 CPU 只警告。
- **复用**：默认关闭；`reuse_found` / `--reuse-found` 开启、任务级 `reuse_found=false` 可关闭。复用阶段在断点创建前测试内存缓存（已完成/已耗尽的任务也会先复用），不写水位、不影响索引；只有 `FOUND`（引擎已完整复核）的密码进入缓存，退出即清空。并行时按任务启动快照，只对之后启动的任务生效；需要确定性复用请 `--max-parallel 1`（CLI 会警告）。
- **命令**：`acx batch jobs.toml [--max-parallel N] [--reuse-found] [--fail-fast] [--dry-run]`；退出码按“停止 4 > 失败 3 > 校验 2 > 有命中 0 > 全未命中 1”。
- **测试**：150 core / 83 CLI passed（1 ignored）/ 2 FFI；批量端到端 14 个（四种模式 dry-run、三任务失败隔离、并行全命中、断点独立续跑、复用开关/已完成断点复用、fail-fast、清单错误、缺归档、超 `usize`/空字典校验、dry-run 线程预算、单任务参数混用）。
- **跨平台**：Windows x64 已验证；Linux/macOS 由 CI 编译/单测覆盖，Ctrl+C 停止传播未在非 Windows 验证。

**首版未实现 / 已知限制**：

- 跨运行“跳过已命中的任务”：命中任务的 W1 检查点按既有语义删除，再次运行同一清单会重新测试该任务；首版不引入批量状态文件（避免新增持久化面）。
- 停止传播依赖 Windows 控制台处理器；非 Windows 仍按默认 SIGINT 终止。
- 并行复用是尽力而为：任务启动时快照缓存，运行中的任务不会中途重试；确定性复用请串行。
- 检查点清理失败不会把命中/未命中改判为失败，只追加 warning（单任务退出码可能因此与旧版不同）。
- 未做 20+ 包/1M 候选级批量基准；空间估算仍不含归档会话。
- 批量 dry-run 会为字典任务扫描字典计数，大字典下预演有明显 I/O。

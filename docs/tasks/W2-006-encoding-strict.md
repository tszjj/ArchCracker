## 设计目标

解决「非 ASCII 密码因编码猜测而被漏报」的问题。同一个密码在不同归档格式里要求不同的字节表示：ZIP 无 UTF-8 标志时按 CP437 或 GBK，RAR4 按 Windows OEM 代码页，7z 按 UTF-16LE。候选源目前只给出一种字节序列，遇到这些格式就会静默漏报。面向中文、日文等非 ASCII 密码场景，让用户能枚举一个候选的多种编码表示，并提供严格模式作为可信回退，让 QA 能用计数做差分。达到的效果是：非 ASCII 已知密码在四种格式的语料上不再因编码猜测漏报，严格模式与默认模式的命中率可对照，快筛边界不被放宽。

## 1. 需求与功能对照

| 需求 | 功能 | 作用 |
|---|---|---|
| 非 ASCII 密码不能因编码猜测漏报 | 每候选的编码变体列表 | 同一文本按多种字节表示尝试，不靠单一猜测 |
| ZIP 无 UTF-8 标志 | CP437 / GBK 变体 | 覆盖旧版 ZIP 的本地编码 |
| RAR4 | OEM 代码页 / UTF-8 变体 | 覆盖 Windows 本地编码与规范编码 |
| 7z | UTF-8 → UTF-16LE 转换 | 由引擎内部完成，非 UTF-8 候选不再一律判未命中 |
| 用户与 QA 需要可信回退 | `--strict` | 关闭所有可能漏报的快筛，代价是性能 |
| 只怀疑 RAR5 快筛 | `--rar-no-fast-reject` | 精细关闭 RAR5 校验快筛，保留其他快筛 |
| 差分验证 | 编码/快筛计数 | 记录每个候选尝试了哪些编码、快筛否决多少次，支持默认与严格模式对照 |
| 批量场景需要携带开关 | 任务清单 / 运行选项增加字段 | 复用 W2-005 的执行路径，不另建旁路 |

## 2. 核心概念

- **候选字节**：字典、掩码、暴力、混合四种候选源产出的原始字节，可能是 UTF-8、GBK 或其他编码。
- **编码变体**：把候选字节按目标格式要求的编码重新表示，得到多条字节序列。**关键取舍：变体在验证阶段展开，不进入候选源**——候选索引是断点的唯一依据，插入变体会改变索引与密码的对应关系（与 W2-005 复用预阶段同理）。
- **候选完成**：一个候选的所有适用变体都试完才算完成；水位按候选推进，不按变体推进。
- **快筛**：只用于否决、不产生命中的判据。本切片负责提供关闭开关与计数，W2-007 补全具体快筛；已有 RAR5 校验快筛的 ASCII-only 边界不变。
- **严格模式**：关闭所有「可能漏报」的快筛，命中仍由归档引擎完整复核，和默认走同一条命中路径；命中结果不来自快筛。

## 3. 与现有架构的关系

- **执行路径**：通过 W2-005 抽出的 `run_job(攻击配置, 运行选项) -> 任务报告` 传入编码与严格选项，单任务与批量共用；不新增旁路。
- **候选源与调度**：四种候选源、批次窗口、水位位图都不变；变体只在引擎验证前展开，`CandidateSource` 的全局语义不动。
- **断点指纹**：编码变体集合与严格开关必须写进攻击指纹的规范化签名，否则改了选项后续跑会静默混用旧断点。格式 v2 不变（只改签名文本内容）。
- **引擎边界**：ZIP/7z 用内置库，RAR 仍只通过外部 UnRAR 进程；不复制或链接任何 RAR 源码，不做 RAR 解压/压缩。
- **估算**：时间估算增加「变体倍数」说明（每条候选最多试几种编码），空间位图仍按候选数计算不变；归档会话仍不纳入。

## 4. CLI 与批量清单

```text
acx -f <archive> -d <dict> --encoding-variants auto|utf8|gbk|cp437|oem \
    [--strict] [--rar-no-fast-reject] [--report-stats]
```

- `auto`（默认）按归档格式选择适用变体；`utf8/gbk/cp437/oem` 可显式指定或组合；不可表示的字符跳过该变体，不报错。
- `--strict` 关闭全部可漏报快筛；`--rar-no-fast-reject` 只关 RAR5 校验快筛，两者可叠加。
- `--report-stats` 在结果中输出编码尝试次数、快筛否决次数、外部复核次数；批量清单的 `[[jobs]]` 增加同名字段，任务报告增加计数，供 W2-007 差分使用。
- 日志与断点不写明文密码；计数只含统计值。

## 5. 后续功能

非首版必需：更多编码预设（如 `cp1252`、`shift_jis`）、编码自动检测结果报告、小键空间编码导出字典、界面编码选择开关。

## 6. 验收

1. ZIP 无 UTF-8 标志的中文密码（GBK 与 CP437 样本）命中；ZIP 有 UTF-8 标志的密码仍命中；
2. RAR4 OEM 代码页与 UTF-8 密码命中，不可表示字符按变体跳过而非静默漏报；
3. 7z 的 UTF-8 / UTF-16LE 路径命中，非 UTF-8 候选不再一律判未命中；
4. RAR5 非 ASCII 仍回退外部进程，快筛的 ASCII-only 边界不变；
5. `--strict` 在语料上默认与严格模式命中率一致（0 漏报），快筛计数与耗时可按预期变化；`--rar-no-fast-reject` 只影响 RAR5；
6. 编码选项或严格开关变化时 `--resume` 拒绝旧断点；
7. 单任务与批量 CLI 均输出编码/快筛计数，批量报告含每任务计数；
8. `cargo fmt`、`clippy -D warnings`、`cargo test --workspace` 通过，新增编码转换单测（含不可表示字符）与四种格式的端到端用例；跨平台影响写明（Windows 验证、其他未验证）。

## 许可与评审意见

RAR 仍只通过外部未修改的 UnRAR 进程，快筛边界不变；不复制或链接任何 RAR/7-Zip 源码，hashcat 未成为依赖，许可边界不变。无新增依赖预期；若引入编码转换 crate 须通过许可检查并登记 `docs/licensing.md`。`--strict` 的关闭范围与快筛边界需 architect 复核，发布前由 release 复核 RAR 许可不变。

## 7. 风险与待定问题

- OEM 代码页依赖 Windows 区域设置，可能产生平台差异，需在 CI 矩阵中说明；
- 变体倍数会放大验证成本，需给出实测 p/s 变化而非估算；头加密归档按候选重新解头的成本会被变体叠加；
- 7z 引擎内部已做 UTF-16LE 转换，需去重避免重复尝试；
- W2-007 新增快筛后，必须同步纳入 `--strict` 的关闭范围与计数，否则严格模式出现缺口；
- 与 W2-005 复用缓存的交互需定义：复用的已命中密码是否按当前编码变体列表重试；
- 第三方头加密语料仍不足（W1-010 遗留），差分结论需注明覆盖范围。

## 8. 实现记录（2026-11-27）

- **编码变体**：`acx-core::encoding` 提供 `EncodingSelection`（`auto` 或显式列表）、按格式解析的 `EncodingPlan` 与验证阶段包装器。变体不进入候选源，候选水位仍按候选推进；一个候选的所有变体试完才算完成。
- **各格式默认集合**：ZIP = UTF-8 / GBK / CP437；RAR4 = UTF-8 / OEM（外部引擎内部将 UTF-8 转 OEM，不可表示时跳过）；RAR5 = UTF-8；7z = UTF-8（引擎内部转 UTF-16LE，变体不重复展开）。显式指定引擎内部已处理的变体会报错。
- **不可表示字符**：GBK/CP437/OEM 编码失败时跳过该变体并计数，不把整个任务判失败；RAR 外部引擎的 OEM 编码失败也按 Miss 处理。
- **严格模式**：`--strict` 关闭 RAR5 check 快筛与 7z 首块探测，直接走完整 CRC/HMAC 复核；`--rar-no-fast-reject` 只关 RAR5。命中仍由归档引擎完整复核，快筛只否决。
- **计数**：`JobStats` 汇总编码尝试、候选数、跳过变体、快筛否决、外部复核；单任务 `--report-stats` 输出，批量每个任务固定输出一行。
- **指纹**：编码选项、`--strict`、`--rar-no-fast-reject` 任一非默认值时，攻击签名追加规范化选项后再取 SHA-256；全默认值保持原有签名，避免破坏已有 W1/W2 检查点。
- **CLI/批量**：新增 `--encoding-variants`、`--strict`、`--rar-no-fast-reject`、`--report-stats`；批量 `[[jobs]]` 支持同名字段。`--estimate` 增加“最多 N 个编码变体”的说明。
- **测试**：156 core / 93 CLI passed（1 ignored）/ 2 FFI；新增编码单测 6 个与端到端 9 个（ZIP GBK/CP437/UTF-8、7z 中文严格模式、统计、估算倍数、续跑拒绝选项变化、批量字段、显式变体拒绝）；本机 WinRAR 6.24 额外验证 RAR4 `-ma4` 中文密码/OEM 路径。
- **跨平台**：Windows x64 已验证 CP437/GBK/OEM 与 RAR4 中文路径；非 Windows 的 OEM 回退为 CP437；Linux/macOS 仅 CI 编译/单测。

**首版未实现 / 未验证**：

- RAR4 非 ASCII 端到端已在本机 WinRAR 6.24 通过；CI 无 RAR 引擎，自动跳过该用例。
- 非 Windows OEM 与 Windows 区域设置差异未做对照；OEM 回退固定 CP437。
- 未做编码变体带来的 1M 级 p/s 基准；变体只增加验证次数，不改候选水位。
- 7z 的“非 UTF-8 原始候选”仍依赖 UTF-8 变体；7z 引擎内部完成 UTF-16LE 转换，不额外展开变体。
- W2-007 新增快筛后仍需纳入 `--strict` 关闭范围与计数。

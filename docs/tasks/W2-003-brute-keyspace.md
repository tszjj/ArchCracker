# W2-003：暴力/键空间

- 状态：首版完成（2026-11-27，PR #26 已合并）；决策已关闭
- 日期：2026-11-27
- 门禁：属于 W2 准出项；界面之前完成
- 角色：core-engineer、reviewer；接口与断点决策需 architect 复核
- 分支：`feat/w2-003-brute-keyspace`
- 依赖：W1-006 调度与断点、W1-007 候选源、W2-002 字符集解析器与断点格式 v2
- 范围：字符集 + 长度区间的暴力候选源、短密码优先、CLI 攻击模式、检查点续跑、估算；不含掩码表达式、混合/规则、GPU/hashcat、界面

## 设计目标

解决「密码长度未知、只有模糊线索时逐条写掩码太笨重」的问题。面向「由小写字母和数字组成、1–8 位」这类场景，用户给字符集和长度区间，内核按短密码优先遍历整个键空间。它与掩码共用同一套候选源、调度和断点，不新增第二套并发逻辑。

## 1. 需求结论

- 采用内核候选源，不生成完整字典文件；
- 长度区间用 `--min-len`/`--max-len`，按长度递增遍历；
- 字符集复用 W2-002 的内置与自定义集合语法；
- 键空间用 128 位整数估算与展示，执行侧维持机器字长索引，超限拒绝；
- 断点复用 W2-002 的通用攻击指纹，模式标记为暴力；
- 小键空间导出字典为后续功能，非首版。

## 2. 约定

| 项 | 约定 |
|---|---|
| 字符集表达式 | 同 W2-002：`?d ?l ?u ?s ?a ?1..?4` + 字面量；`?b` 不实现，非 ASCII 报错 |
| 自定义字符集 | `--custom-charset1..4`，规则同 W2-002（可含内置集合与字面量、展开去重、不递归、≤256 字节） |
| 长度区间 | `--min-len N --max-len M`，均 ≥1，`min > max` 报错，上限 128 |
| 遍历顺序 | 长度从小到大；同一长度内按字符集顺序做里程表递增；字面量进入字符集，不产生固定位置（固定位置用掩码模式） |
| 总键空间 | 各长度键空间之和，128 位估算；执行侧要求不超过机器字长上限 |
| 进度索引 | 全局索引跨长度累计；续跑时按累计划分区间映射到具体长度与局部索引 |

## 3. 框架设计

类型：`BruteSpec`（字符集、原文、最小/最大长度）、`BruteSource : CandidateSource`（各长度累计前缀、当前长度、计数位、全局索引）、`BruteEstimate`（键空间、是否可执行、各格式 ETA、警告、空间估算）。

生成：按长度依次处理，把全局索引减去该长度累计前缀后解码成计数位，按里程表递增产出候选；一个长度耗尽切到下一个，全局索引保持连续；遵守 4096 在飞候选（候选 ≤128 字节，无单独 8 MiB 批上限；8 MiB 只用于字典/混合源）。

**与调度器的取舍**：不做独立键空间分区器，改用 `CandidateSource` 暴露总数与下一批，分片由调度器按批次完成；与掩码共用同一条调度/断点路径，避免第二套并发逻辑。

**执行侧索引决策（已定）**：维持机器字长索引，不扩到 128 位。64 位上限约 1.84e19，按实测 ZIP 25,423/s 计算，24 小时可尝试 2.2e9，上限对应约 2.3 万年，远高于任何实际可完成的攻击。扩到 128 位需改动批次索引、总数、调度器水位位图、断点字段和全部调度测试，并需重跑 1GB 矩阵，收益极低、回归风险集中在最不能出错的模块。128 位只用于估算展示，超限时打印「仅估算」并拒绝攻击。此决策同时关闭 W2-002 的对应待定问题，混合模式沿用同一上限。

断点：复用格式 v2，模式标记为暴力；签名为字符集原文 + 4 个自定义集原文 + 最小/最大长度，用固定分隔符连接后取 SHA-256；任一变化拒绝续跑；全局索引按长度前缀二分定位，落在边界时从下一长度第 0 个候选继续；旧格式断点直接拒绝。

CLI：`--brute`、`--min-len`、`--max-len`、`--custom-charset1..4`、`--estimate`；与字典、掩码模式互斥；估算输出增加字符集、长度区间与各长度键空间。

## 4. 验收

- 解析：内置/自定义字符集、字面量、去重、ASCII 限制、长度区间校验；
- 键空间与手算一致，128 位估算，超限明确报错；
- 生成：跨长度边界不重不漏，短密码优先顺序稳定，1M 候选无异常；
- 恢复：续跑从全局索引继续，长度边界不跳过候选；
- 估算：ETA、24h 容量与警告，`--estimate` 不启动攻击；
- 指纹：字符集或长度区间变化拒绝续跑，与掩码模式互通；
- 性能：生成开销不成为验证瓶颈，批次内存遵守 W1 上限。

## 5. 后续功能

导出字典、多字符集集合、隐藏式递增、估算 JSON 输出、运行时进度。

## 6. 实现记录（2026-11-27）

内核实现字符集展开与指纹复用掩码模块的共享函数，没有第二套解析器；CLI 参数与互斥如上，退出码沿用 0/1/2/3/4；估算支持逐长度打印键空间；空间估算与掩码/混合共用公共函数。

测试：合并时 123 core / 58 CLI（1 忽略）/ 2 FFI；空间估算回填后全仓 144 core / 69 CLI（1 忽略）/ 2 FFI。新增 16 个内核单测（顺序、批次边界、全索引续跑、1M 生成、单字符集合、128 位上限与溢出、警告、指纹）与 14 个端到端用例（命中、自定义字符集、估算与警告、长度边界续跑、参数变化拒绝续跑、参数互斥、超限拒绝）。

跨平台：Windows x64 已验证；Linux/macOS 为纯 Rust 逻辑，只保证 CI 编译与单测，未做运行时验证。

## 许可与评审意见

`sha2` 已是既有依赖，无新增许可登记；与掩码共用解析器，字符集定义变化需同步更新本文。首版决策：单一字符集，权重/常用字符优先不做。评审通过。已知限制：超长区间可能实际不可完成；水位位图随键空间线性增长，估算已输出字节数与警告；RAR 外部进程每候选成本高，实际可尝试量远小于 ZIP。未做 1M×1GB 端到端基准（仅 1M 候选生成单测），7z/RAR 未单独跑暴力端到端（与 ZIP 共用同一路径）。

# W2-002 掩码攻击：需求分析与框架设计

- 状态：首版完成（2026-11-27，PR #23 已合并；掩码文件、`?b`、界面生成后续）
- 日期：2026-11-26
- 范围：掩码表达式、空间/时间估算、警告策略、内核候选源框架
- 关联：[W2-PLAN](../W2-PLAN.md)、[W1-010 基准](../benchmarks/W1-010.md)、[W1-009 基准](../benchmarks/W1-009.md)
- 约束：只做 CPU 路径；不做界面；不启动 GPU/hashcat

## 设计目标

解决「密码结构已知但逐条写字典太笨重」的问题。面向用户能描述出字符类型与长度的场景（如「首字母大写 + 3 个小写 + 2 位数字」），用一行掩码表达式描述整个候选集合，内核按批次生成，不展开成字典文件。攻击前先估算空间与时间并给出警告，让用户启动前就知道任务是否可执行。

实现状态：已落地 `MaskSpec`/`MaskSet`/`MaskSource`、`--mask`/`--custom-charset1..4`/`--estimate`、断点格式 v2；实现文件见 `core/crates/acx-core/src/candidates/mask.rs`、`checkpoint.rs`、`acx-cli/src/main.rs`。

## 1. 需求结论

采用内核候选源 + CLI 攻击模式，不把掩码完整展开成字典文件：

- CLI 用掩码表达式描述候选集合；内核按批次生成交给调度器；
- 支持暂停、停止、检查点与续跑；
- 攻击前先做空间/时间估算，过长或过大的表达式先警告；
- 界面的「规则描述 → 字典文件」不属于 W2，留到 W3 或独立工具。

## 2. 表达式约定

| 项 | 约定 |
|---|---|
| 字符集 | ASCII；非 ASCII 字面量报错 |
| 最大长度 | 128 个位置（硬上限）；>16 个位置产生警告 |
| 表达式原文长度 | ≤512 字节 |
| 内置集合 | `?d` 数字 10；`?l` 小写 26；`?u` 大写 26；`?s` 33 个 ASCII 符号（含空格）；`?a` 可打印 ASCII 95 |
| 自定义集合 | `?1..?4`，每个展开后 ≤256 字节，由 `--custom-charset1..4` 定义 |
| `?b` | 首版不实现（与命令行/外部 RAR 的行输入冲突），后续单独评审 |
| 转义 | `??` 表示字面 `?`；未知 `?x` 报错 |
| 长度范围 | 单条掩码固定长度；用多条 `--mask` 表达，不做隐式递增 |
| 最大键空间 | `usize::MAX`（受批次索引用 `usize` 限制）；`u128` 仅用于估算 |

内置集合展开：`?d=0123456789`；`?l=abcdefghijklmnopqrstuvwxyz`；`?u` 为对应大写；`?s` 为 33 个 ASCII 符号（含空格，shell 中需整体引用）；`?a=?l?u?d?s`。

语法：`position := literal | "??" | ?d/?l/?u/?s/?a | ?1..?4`。示例：

```text
?d?d?d?d                 4 位数字
?u?l?l?l?d?d             首字母大写 + 3 小写 + 2 数字
PREFIX-?1?1?1            固定前缀 + 3 个自定义字符
??d?d?d                  字面 '?' + 'd' + 两位数字
--mask "?1?1?1?1" --custom-charset1 "?d?l"
```

自定义集合可含内置集合与字面量，展开后去重，不允许递归引用自身或其他未展开集合，最多 4 个。

**警告**（继续前打印）：长度 >16；键空间 >2³²；预计 24 小时内无法完成。

**硬错误**（拒绝执行）：长度 >128；表达式 >512 字节；非法 `?x`、未定义自定义集、自定义集超限、递归引用；键空间或多条合计超过 `usize::MAX`；空掩码或纯空白。

警告不改变退出码；`--estimate` 只打印估算，不启动攻击。

## 3. 空间与时间估算

**空间**：不生成完整键空间或字典。解析占 `O(L+C)`；批次按 4096 在飞候选（掩码候选 ≤128 字节，无单独 8 MiB 批上限；8 MiB 上限只用于字典/混合源）；水位位图 `ceil(keyspace/8)` 字节 + `(threads+3)` 个在飞批次 + 源缓冲，位图 >128 MB 时警告（公共函数见 [W2-003a](W2-003a-space-estimate.md)）。估算不含归档会话。

**时间**：`总时间 ≈ 键空间 / 实测候选率`，`24h 容量 ≈ 实测候选率 × 86400`。速率按本项目 1.3 GB / 14 线程实测，不是理论峰值：

| 格式 | 实测候选率 | 24h 最大尝试量 |
|---|---:|---:|
| ZIP AES | 25,409/s | 2,195,337,600 |
| 7z AES | 967.9/s | 83,626,560 |
| RAR5 快筛 | 1,727.2/s | 149,230,080 |
| RAR5 外部整包测试 | 221.5/s | 19,137,600 |

这是「可尝试验证」的候选数，不是保证命中的数量；非 ASCII、外部 RAR 与后台负载都会让实际值更低。更高核心数 CPU 只做线性上界（32 线程 ZIP 约 58,078/s，24h 约 5.02e9），未实测，仅用于容量规划。

常见掩码的 ZIP 时间只作数量级参考，实际以 `--estimate` 为准：6 小写约 3.4 小时；8 数字约 1.1 小时；8 小写约 95 天；10 位数字约 4.6 天；8 位全可打印约 8,274 年。

## 4. 框架设计

类型：`MaskSpec`（位置集合、4 个自定义集、原文、长度）、`MaskPosition`（字面字节或字符集编号）、`MaskSource : CandidateSource`（总数、下一批）、`MaskEstimate`（键空间、是否可执行、警告、空间估算、ETA）。

生成：解析为位置数组，每位置展开为去重且顺序稳定的字节集合；键空间为各位置长度乘积，`u128` 估算、超过 `usize` 拒绝执行；批次起点解码成各位置计数后按里程表递增；只维护计数向量与输出缓冲，不按候选做除法或分配。

调度：实现 `CandidateSource`，不改调度器 API；总数必须准确、批次起点连续；检查点记录掩码指纹与全局索引，不记录密码；暂停/停止沿用 W1 机制。

CLI：`--mask`（可重复）、`--custom-charset1..4`、`--estimate`；与字典模式互斥；估算按归档格式选择实测速率。

估算输出示例：

```text
mask: ?u?l?l?l?d?d
keyspace: 1,757,600
fits executable index: true
watermark bitmap: 219,700 B (0.2 MB)
format: zip (25,409/s measured)
eta: 69.2 s
24h capacity: 2,195,337,600 candidates
```

超过 24 小时时打印警告（如「预计 95.1 天，24 小时容量 2.20e9」）。

**检查点**：采用断点格式 v2，新增通用攻击指纹；掩码/暴力的字典字段为空，混合模式非空。指纹记录 `attack_mode` 与规范化描述的 SHA-256；多条掩码按命令行出现顺序拼接，附 4 个自定义集原文，用固定分隔符连接后取哈希。总数是各条键空间之和，全局索引二分定位到具体掩码与局部索引；落在掩码边界时从下一条的第 0 个候选继续。旧格式断点直接拒绝，不做半兼容读取。

## 5. 验收

- 解析：合法/非法 token、`??`、自定义集、去重、ASCII 限制；
- 键空间与手算一致，`u128` 估算，超限明确报错；
- 生成：批次边界不重不漏，候选顺序稳定，1M 候选无异常；
- 恢复：暂停/停止/检查点，续跑从索引继续；掩码边界不重不漏；
- 估算：ETA、24h 容量与警告文本，`--estimate` 不启动攻击；
- 性能：生成开销不成为验证瓶颈，批次内存遵守 W1 上限。

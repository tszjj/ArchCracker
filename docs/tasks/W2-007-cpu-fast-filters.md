## 设计目标

解决「批量任务下每个错误候选都要做完整解压或启动外部进程，吞吐被验证成本压死」的问题。当前 ZIP 与 7z 已有部分判错手段（校验字、头 CRC、首块探测），RAR5 已有 ASCII-only 校验快筛，但它们零散、未被统一计数覆盖，RAR4 也没有快筛。本切片在**不重写现有引擎判据**的前提下，把可安全否决的判据接入统一的计数/严格模式契约，补充 ZIP 的密码 verifier 快筛，收敛 7z 的错误分类，并对 RAR4 `-hp` 首头校验给出 go/no-go 结论。

达到的效果是：错误候选尽量在进程内被否决，命中仍走完整复核；每个可表示的编码变体都独立经过快筛；`--strict` 可关闭本切片全部新增判据；默认与严格模式的命中率可对照；快筛否决、完整验证与外部调用可量化。

## 1. 目标用户与使用场景

| 用户 | 场景 | 本切片为其解决什么 |
|---|---|---|
| 恢复大量错误候选的终端用户 | 一本大字典 × 多个归档，绝大多数候选是错的 | 减少 ZIP 完整解压；RAR4 `-hp` 若可行则减少外部 UnRAR 调用 |
| 中文/非 ASCII 密码用户 | 候选需按多种编码尝试 | 每个可表示编码变体都独立经过快筛，不得被错误否决 |
| QA 与审计人员 | 对比默认模式与严格模式的命中率、统计快筛否决次数 | 用计数和小语料证明「0 误杀、0 漏报」；0 误报由完整复核保证 |
| 批量任务用户 | `acx batch` 跑 20+ 包 | 每任务报告带快筛/完整验证/外部调用计数，定位异常包 |

## 2. 定位与 W2-006 的关系

**W2-006 提供「开关与基础计数」，W2-007 提供「判据与缺失指标」。** 两者职责不重叠：

- W2-006 已建立 `--strict`（关闭全部可能漏报快筛）、`--rar-no-fast-reject`（只关 RAR5 校验快筛）、`--report-stats` 与任务报告字段，并规定「快筛只否决、不产生命中」。当前 `JobStats` 包含：编码候选/尝试/跳过变体、`fast_rejected`、`external_confirmed`（仅外部命中）。
- W2-006 **没有**提供「完整验证次数」和「外部进程调用次数」；`external_confirmed` 不是调用次数。W2-007 需要新增 `full_attempted`（完整验证尝试，含 Miss/错误）与 `external_attempts`（外部进程调用），并接入单任务/批量报告。
- W2-007 沿用 `RarSession`/`SevenZSession` 现有内部判据，通过**适配器/统计契约**接入，不做「把所有私有分支重写成同一个 trait」的重构；W1-004/W1-009 的稳定路径不重写。

**接口契约（W2-007 必须遵守）**：

```text
快筛判据 = 对候选的一种「可证明只否决」的判定
  输入: 候选字节 + 归档会话状态 + 运行选项（严格/编码变体）
  输出: Reject（明确不是密码） | PassThrough（无法否决，继续完整验证）
  约束: 永不输出 Hit；命中只能由归档引擎完整复核产生

每个判据必须:
  - 受 --strict 统一关闭（含仅关 RAR5 的精细开关语义）
  - 写入快筛计数（按格式、按判据分别计数）
  - 若判据有可配置参数，纳入断点指纹签名；无可配置参数时不改变默认签名
```

## 4. 非功能性目标

### 4.1 性能

- **P1（条件目标）**：先测 ZIP 当前基线与 `zip` crate 是否已在完整验证内部做密码 verifier；只有实测证明新增判据减少完整解压/验证成本时才宣称收益。报告必须给 before/after，不引用未实测数字。
- **P2**：快筛判定耗时相对其替代的完整验证成本可忽略；基准记录快筛耗时占比。
- **P3（条件目标，仅 RAR4 go 时）**：RAR4 `-hp` 负例的外部 UnRAR 调用次数下降，并被 `external_attempts` 计数证实；若 RAR4 no-go，P3 不适用。

### 4.2 可扩展性

- 新判据以适配器接入统一统计/严格模式契约，不改调度器、候选源或 CLI 主流程；
- 判据清单集中维护，新增判据的接入点不超过一处；
- 不为了「统一」重写引擎内部判据。

### 4.3 兼容性

- 断点格式 v2 不升版；判据配置变化通过签名文本体现，`--resume` 拒绝不匹配配置；无可配置参数的判据不改变默认签名；
- 与 W2-006 的编码变体共存：**每个可表示变体**独立经过快筛；不可表示变体计入 `skipped`，不进入验证，不属于「跳过快筛」；
- RAR5 ASCII-only 快筛边界不变，非 ASCII 候选继续回退外部。

### 4.4 可维护性与计数口径

- 判据与引擎会话分离，每个判据有独立单测，含「应否决」「应放行」「不可判定」三类用例；
- 计数与错误分类使用统一枚举，避免各格式自定义字符串；
- 计数公式：

```text
candidates      = 源候选数（水位单位）
tried           = 已完成的源候选数
variant_slots   = 每个候选去重后的变体数之和（含因不可表示而跳过的变体）
attempts        = 实际尝试的编码变体数
                = fast_rejected + full_attempted
variant_slots   = attempts + skipped
candidates <= variant_slots
full_attempted  = 进入完整验证的尝试数（含 Miss、错误；不是成功数）
external_attempts ⊆ full_attempted（RAR 外部路径；不要与 full_attempted 重复相加）
除 candidates/tried 外，各项均按编码变体尝试计数
误杀 false reject = fast_rejected 中错误拒绝了正确密码的数量；必须为 0
误报 false positive = 命中结果不是真密码；快筛不产生 Hit，完整复核保证 0
漏报 false negative = 严格/默认模式漏掉已知密码；必须为 0
```

## 6. 关键约束与假设

- **正确性优先**：快筛只否决、不产生命中；任何不确定情况一律放行到完整验证。
- **7z 无认证器**：候选级 CRC/解压失败统一按 Miss/候选被拒，不做「密码错/损坏」二分；仅归档级打开/结构/I/O/不支持错误分类。
- **RAR4 范围**：仅评估 `-hp` 头加密；普通 RAR4 无等价首头校验，维持外部进程。若实现需要 RAR4 AES-128 头解密，新增依赖/许可须单独评审。
- **RAR 许可边界**：不解压 RAR、不链接或复制 UnRAR 源码、不做自研 RAR 解码；RAR4 评估越界即 no-go。
- **hashcat 不是 Cargo 依赖**：GPU 不在本切片范围。
- **命中复核路径不变**：ZIP/7z 走内置完整解压，RAR 走外部 `UnRAR t`。
- **时序**：W2-006 已完成（PR #33）；W2-008 的全量语料/差分/1M 基准在本切片之后，不阻塞 W2-007 关闭。

## 8. 验收标准（可衡量）

1. **契约统一**：ZIP/7z/RAR5 否决均进入统一统计/严格模式契约；RAR5/7z 内部实现保留，不以「无私有分支」作为验收条件；
2. **0 误杀 / 0 误报**：小型差分语料上被快筛否决的候选，经完整验证确认无一是正确密码；所有命中均经完整复核，无错误命中；
3. **0 漏报**：`--strict` 与默认模式在已知密码语料上命中率一致；
4. **RAR4 结论**：产出 `-hp` go/no-go 文档；若 go，快筛只否决且不越过许可边界；若 no-go，普通 RAR4 与 `-hp` 均继续外部进程；
5. **计数正确**：`--report-stats` 与批量报告按判据给出否决数、`full_attempted`、`external_attempts`；满足 §4.4 公式，`variant_slots >= candidates`；
6. **签名生效**：改变可配置判据参数后 `--resume` 拒绝旧断点；无可配置参数时不改变默认签名；
7. **编码共存**：W2-006 的每个可表示编码变体均独立经过快筛；不可表示变体计入 `skipped`；
8. **性能证据**：给出 ZIP before/after（若实现）与 RAR4 外部调用计数（若 go）；无未实测百分比；
9. **质量门禁**：`cargo fmt`、`clippy -D warnings`、`cargo test --workspace`、MSRV 1.89、release、cargo-deny 全绿；
10. **跨平台说明**：Windows x64 已验证；其他平台写明已验证/未验证；
11. **W2-008 边界**：全量差分/1M 基准不在本切片关闭条件内；W2-008 负责补齐并引用本切片判据清单。

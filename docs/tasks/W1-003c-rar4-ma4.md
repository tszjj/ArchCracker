# W1-003c：RAR4 `-ma4` 端到端验证

- 分支：`fix/w1-003c-rar4-ma4`
- 角色：core-engineer、reviewer
- 状态：完成（PR #7，评审通过，CI 6/6）
- 前置：[W1-003](W1-003-rar-external.md)

## 设计目标

解决「RAR4 只在代码路径上覆盖、没有真实样本验证」的问题。面向使用旧格式 RAR4 归档的用户，用 WinRAR 6.24 生成的真实样本补齐端到端验证，并修正 RAR4 与 RAR5 在外部引擎退出码上的差异，避免错误密码被当成引擎错误中止。

## 关键发现

- RAR4 缺密码 `t -p-` 返回 3（RAR5 是 11）；错误密码的候选测试同样返回 3，原实现会误判为外部错误。
- 文件加密时 `l -p-` 返回 0，清单中加密条目前有 `*`；头加密时返回 3，主头含 `0x0080` 标志。
- 未加密但损坏的 RAR4 也可能返回 3，须用主头标志区分头加密与损坏。
- `l -idq` 会抑制清单输出，拿不到 `*` 标记，故去掉该参数（清单仍受 64 KiB 截断保护）。

## 实现要点

预检新增 RAR4 退出码 3 的分支：清单成功且有 `*` 标记 → 文件加密；清单返回 3 且主头含 `0x0080` → 头加密；其余按损坏报错，不进入字典。候选测试把 RAR4 的 3 映射为未命中（RAR5 的 3 仍算引擎错误）。新增 4 个单测覆盖退出码分类、主头标志与 `*` 标记；CLI 集成测试生成 `-ma4` 样本验证命中、错误字典、未加密与损坏归档。

## 验收

```powershell
cd core
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

`-ma4` 样本标识为 RAR4；正确密码 exit 0、错误字典 exit 1、未加密 exit 3、损坏归档 exit 3 且不进入字典；`-hp` 头加密手工验证通过。

## 结果

core 46（新增 4）+ CLI 4 + 集成 9 + FFI 2 通过；本机 3 个 RAR 集成实际执行未跳过。手工（WinRAR 6.24）覆盖 RAR4 文件加密、头加密、未加密、损坏归档。

## 许可与引用

RAR 仍只通过外部 UnRAR 进程，许可边界不变，无新依赖。样本由本机 Rar.exe 生成，不提交仓库。

## 评审与对照意见

评审通过。已知边界：RAR4 退出码 3 语义不唯一——密码正确但数据损坏时仍按未命中，最终可能显示「未找到」而非明确损坏；清单 `*` 标记依赖 UnRAR 输出格式，需在更多版本上回归；分卷/SFX、其他代码页、超大归档未覆盖，非 Windows 平台未做运行时验证。

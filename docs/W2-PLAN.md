# W2 阶段目标划分（计划）

- **状态**：已批准启动（W1 signoff 2026-11-26）；从 W2-002/003 开始
- **周期**：2–3 周
- **平台**：Windows 10/11 x64 CLI；GUI 仍属 W3
- **GPU**：W2-001 已推迟，W2 不启动 hashcat/GPU

> 每节的“实现目标/设计目的”是拆解参考，**不作为准出标准**；准出只按 §4 和任务文档验收。

## 1. W2 目标

在 W1 的 ZIP/7z/RAR + 字典 + 流式 + 断点基础上，补齐 CPU 攻击面、批量和编码变体，使 Windows CLI 达到 beta 可用。

## 2. 爆破/攻击：内核实现还是生成字典

W2 前段（W2-002/003/004）有两种做法：

| 维度 | 内核候选源（CLI 攻击模式） | 生成新字典文件 |
|---|---|---|
| 内存/磁盘 | 有界内存，不落盘 | 大键空间会生成巨大文件 |
| 恢复 | 按键空间索引/规则位置恢复 | 按文件偏移恢复 |
| 速度 | 无生成/写盘成本 | 先生成再读，额外 I/O |
| 安全 | 密码候选不落盘 | 明文候选可能留在磁盘 |
| 复用 | CLI/未来 GUI/API 共用 | 主要给 CLI/外部工具 |
| 实现量 | 需要 CandidateSource/分区/断点 | 只需生成器，较简单 |
| 适用 | 大键空间、常用攻击 | 小键空间、导出、离线复用 |

**结论：以内核攻击模式为主，生成字典作为辅助能力。**

- W2-002/003/004 在 `acx-core` 内实现 `CandidateSource`，按批次生成候选；不把大键空间完整写成字典。
- 生成字典只用于小键空间、导出/调试、给外部工具复用；W2 可提供 `--export-dictionary` 之类的可选能力，但不作为主路径。
- GUI 上“规则描述 → 字典文件”属于 W3 或另建工具；W2 不依赖 GUI，也不把 GUI 生成器当作攻击引擎。

理由：大键空间用字典文件会不可控地占磁盘、增加生成时间和明文落盘风险；内核候选源可直接复用 W1 的 scheduler、4096 in-flight 窗口、暂停/停止/checkpoint，且 CLI 与未来 GUI 共用同一实现。

## 3. 分片

### W2-001 GPU/hashcat — Deferred

原本打算使用 GPU 算力加速密码验证/爆破；现决定**推迟相关计划**。W2 不启动 hashcat/CUDA/HIP/OpenCL，不新增 GPU 依赖；W2 退出后再重新评估。

### W2-002 掩码攻击

> **状态（2026-11-27）**：内核 MaskSource、CLI `--mask`/`--estimate`、schema v2 checkpoint 已实现并合并（PR #23）；1M 掩码回归 40.458s；`--mask-file`/`?b`/GUI 生成器为后续。
>
> 表达式约定、限值、空间/时间估算和 24h 容量见 [W2-002 需求分析](tasks/W2-002-mask-requirements.md)；首版基准见 [W2-002 基准](benchmarks/W2-002.md)。

**实现目标（参考）**

- 在 CLI 攻击专用模式中支持掩码表达式，如 `?d?d?d?d`、固定前缀/后缀、`?1..?4` 自定义字符集；长度范围首版用多条 `--mask` 表达（`--mask-file` 为后续功能，见任务文档 §6）；
- 在 `acx-core` 内按表达式遍历键空间，按批次产出候选，不生成完整字典文件；
- 支持暂停/停止/checkpoint；恢复只依赖“掩码规范 + 索引”；
- 可选提供小键空间导出字典，供离线/外部工具使用。

**设计目的**

- 大键空间不落盘、不占内存，直接复用 W1 的调度与断点；
- CLI 攻击模式与未来 GUI 共用同一套候选源；
- GUI 的“规则描述生成字典”放在 W3 或独立工具，W2 不依赖它。

### W2-003 暴力/键空间

> **状态（2026-11-27）**：内核 `BruteSource`、CLI `--brute`/`--min-len`/`--max-len`/`--estimate`、schema v2 checkpoint（`mode=brute`）已实现并合并（PR #26）。实现细节、共享字符集解析器和测试见 [W2-003 任务文档](tasks/W2-003-brute-keyspace.md) §9。

**实现目标（参考）**

- CLI 支持字符集 + 长度区间 + 短密码优先；
- 内核按 `usize` 全局索引遍历（批次由 scheduler 分发，不做独立键空间分区器）；`u128` 只用于估算/展示；执行上限与理由见 [W2-003 §4.3–4.4](tasks/W2-003-brute-keyspace.md)；
- 支持 `--resume` 键空间水位；小键空间可选用导出字典。

**设计目的**

- 提供不依赖字典的通用兜底；
- 与掩码共用 `CandidateSource`/scheduler，避免两套并发和断点逻辑；
- 大键空间仍不物化，避免磁盘和明文落盘。

### W2-003a 空间估算回填

> **状态（2026-11-27）**：`acx_core::estimate::SpaceEstimate`、mask/brute 回填、hybrid 复用已实现并合并（PR #28）。位图 >128 MB 时警告；单位十进制 MB。详见 [W2-003a](tasks/W2-003a-space-estimate.md)。

### W2-004 混合/规则

> **状态（2026-11-27）**：规则链、hybrid 候选源、CLI 与 schema v2 复合指纹首版已实现并合并（PR #28）；空间估算复用 W2-003a 的 `SpaceEstimate`。详见 [W2-004 任务文档](tasks/W2-004-hybrid-rules.md)。

**实现目标（参考）**

- 字典 × 固定/掩码前后缀；
- 最小规则子集（大小写、反转、追加/前缀、简单变形），规则语法写进任务文档；
- 流式读取 W1 字典，按批次生成变体；checkpoint 记录字典位置 + 变体索引；
- 可选把小型组合导出为字典。

**设计目的**

- 覆盖“词典 + 前后缀/大小写”的真实攻击；
- 复用 W1 流式字典，避免整本字典进内存；
- GUI 规则编辑器/字典生成器归 W3 或独立工具，W2 只做核心攻击模式。

### W2-005 批量任务/包间复用

> **状态（2026-11-27）**：`acx batch`、TOML 清单、有限并行、失败隔离、每任务断点、内存内命中复用已实现（PR #30）。详见 [W2-005 任务文档](tasks/W2-005-batch-jobs.md) §7。

**实现目标（参考）**

- 任务清单：归档、攻击模式/字典、线程、checkpoint 目录、可选密码复用；
- 串行/有限并行，单包失败隔离，每任务独立状态/断点；
- 密码复用仅在用户显式授权任务组内生效，不写明文日志。

**设计目的**

- 支持真实多包场景，不因一个坏包丢失全部结果；
- 与单任务 checkpoint/CLI 解耦，便于后续 GUI 队列复用。

### W2-006 编码变体与严格模式

**实现目标（参考）**

- ZIP 无 UTF-8 标志的 CP437/GBK 变体；RAR4 OEM/UTF-8；7z UTF-8；
- `--strict` 关闭可能漏报的快筛；`--rar-no-fast-reject` 仅关闭 RAR5 check 快筛；
- 记录候选编码/快筛计数，支持差分。

**设计目的**

- 非 ASCII 密码不能因编码猜测漏报；
- 严格模式作为用户/QA 的可信回退；
- RAR5 的 ASCII-only 快筛边界不变。

### W2-007 CPU 快筛补全

**实现目标（参考）**

- ZIP：评估/实现 verifier/结构判据，只用于否决；
- RAR4：评估头加密首头校验可行性；不越过“不解压 RAR”边界，否则继续外部；
- 7z：复用 W1 头 CRC/首块，补严格模式/计数/错误分类；
- 命中仍由内置引擎或 `UnRAR t` 完整复核。

**设计目的**

- 批量任务下减少外部进程/完整解压调用；
- 快筛只否决、不产生命中；RAR 许可边界优先于性能。

### W2-008 语料/差分/基准

**实现目标（参考）**

- 生成/索引 ZIP/7z/RAR 负例、分卷/SFX、非 ASCII、1GB 条目；
- ZIP/7z 用内置完整验证，RAR 用外部 `UnRAR t` 做 oracle；
- 记录各攻击模式 p/s、CPU、RSS、ETA；报告写入 `docs/benchmarks/W2-*.md`；
- 样本/字典不入库，只记录生成方式和哈希。

**设计目的**

- 为 W2 退出和 W3 GUI 提供可复现证据；
- 让内核攻击模式的收益、快筛风险和编码边界都能被验证。

## 4. 准出标准（唯一）

> 本节是 W2 准出依据；§3 的实现目标只是参考。

- 掩码/暴力/混合/规则可用，已知密码 100%；
- 批量/包间复用/编码变体/严格模式通过语料；
- CPU 快筛 0 误报、严格模式 0 漏报；
- 1M 级基准、p/s/CPU/内存/ETA 记录；无 P0/P1；
- `cargo fmt/clippy/test`、MSRV 1.89、release、cargo-deny、CI 全绿；
- 许可边界不变：RAR 只外部/独立 check，hashcat 不是 Cargo 依赖，GUI 不引入。

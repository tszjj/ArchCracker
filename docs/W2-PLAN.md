# W2 阶段目标划分（计划）

- **状态**：**已批准启动（W1 signoff 2026-11-26）；从 W2-002/003 开始**
- **准入意见**：W1 已签核（[W1-SIGNOFF](W1-SIGNOFF.md)），按本计划进入 W2；W2-001 GPU 继续 Deferred
- **周期**：2–3 周
- **首发平台**：Windows 10/11 x64 CLI；GUI 仍属 W3
- **GPU**：W2-001 已 **Deferred**，W2 不启动 hashcat/GPU

> **参考性说明**：本文每个分片的“实现目标”和“设计目的”只用于拆解、排期和对齐，**不作为准出标准**。准出只按 §5 和对应任务文档的验收项判定；实现手段可以调整，只要 §5 仍满足。不要把本文的目标数字当成硬性门槛。

## 1. W2 目标

在 W1 的 ZIP/7z/RAR + 字典 + 流式 + 断点基础上，补齐 CPU 攻击面、批量和编码变体，使 Windows CLI 达到 beta 可用：

- 掩码、暴力、混合/规则；
- 批量任务/包间复用；
- ZIP/RAR4/7z 的 CPU 快筛和严格模式；
- 编码变体、错误分类和 CLI 状态输出；
- 可复现的差分/负例/基准证据。

**不包含**：GUI、安装包/签名、GPU/hashcat、RAR 解压器/压缩器。

## 3. 分片详述（参考性目标，非准出标准）

### W2-001 GPU/hashcat spike — Deferred

**实现目标（参考）**

- 无功能实现；保持 `W2-001` 任务为 Deferred；
- 不新增 hashcat/CUDA/HIP/OpenCL 的 Cargo 依赖；
- 不启动 GPU 后端、不随包 GPU 运行时。

**设计目的**

- W2 的关键路径是 CPU 攻击面和可验证性，GPU 的驱动/打包/许可风险不应拖慢 W2；
- 保留 W4 Full 版随包 hashcat 的决策，但不在 W2 重新打开；
- W2 退出后再单独评审：是否值得做、用什么边界、如何回退 CPU。

**不做什么**

- 不写“预留 GPU 接口”但无测试的空壳；
- 不让 hashcat 成为 `acx-core` 的库依赖。

### W2-002 掩码攻击

**实现目标（参考）**

- 新增 `MaskSpec`（或等价类型）：
  - 固定字符 + `?d ?l ?u ?s ?a ?b` + 自定义 `?1..?4`；
  - 支持位置集合/固定位置（至少固定前缀、后缀、逐位字符集）；
  - 长度区间 `min_len..=max_len`，短密码优先；
  - 非法字符集、空模式、超长模式明确报错。
- 新增 `MaskSource`：
  - 用 `UInt128` 表达键空间；只按批次生成候选，不物化整个键空间；
  - `total()` 可计算；批次 `start_index` 连续；到末尾正确结束；
  - 支持按索引恢复：`next_index` 可由键空间偏移重建，checkpoint 只存 spec 指纹 + 索引，不存密码。
- CLI：
  - `--mask <pattern>`、`--custom-charset1..4`、`--min/max`（具体拼写以实现时 CLI 设计为准）；
  - 与字典模式互斥；与 `-t`、`--checkpoint`、`--resume` 组合。
- 测试：
  - 解析错误/转义；不同长度总数；索引↔候选映射；批次边界不重不漏；
  - 已知密码 fixture；暂停/停止/断点恢复；小键空间穷举。

**设计目的**

- 把“攻击模式”从“密码验证/调度”中分离：scheduler 只消费 `CandidateSource`，不为 mask 复制一套调度；
- 避免把巨大键空间读进内存，保持 W1 的 4096 in-flight 候选窗口；
- 为 W2-004 混合/规则提供可组合的前后缀掩码；
- 让断点只依赖“规范 + 索引”，比存密码更省空间、更不敏感。

**不做什么**

- 不做 hashcat 全语法/全规则兼容；
- 不保证 GPU 键空间格式；
- 不在 W2-002 做字典×mask 组合（留给 W2-004）。

### W2-003 暴力/键空间

**实现目标（参考）**

- 新增 `BruteSpec`：字符集（内置/自定义）+ 长度区间 + 短密码优先；
- `BruteSource`：
  - 键空间按长度分段；总数为各长度 `charset.len()^len` 之和（溢出时拒绝/回退）；
  - 支持 `UInt128` 分区；一个 worker/断点只处理连续区段；
  - 批次生成与 W1 `CandidateBatch` 对齐。
- CLI：`--brute`/`--charset`/长度区间；
- 测试：小字符集穷举、分区不重不漏、键空间边界、暂停/停止/恢复、非法字符集。

**设计目的**

- 提供不依赖字典的通用兜底；mask 可以表达一部分暴力，但单独实现能给出更简单的 UX、键空间水位和错误提示；
- 与 mask 共用 `CandidateSource`/scheduler，避免两套并发/断点逻辑；
- 明确“短密码优先”和“无界键空间上限”，防止用户误开不可完成任务。

**不做什么**

- 不做分布式/多机键空间；
- 不做 GPU 内核；
- 不做无长度上限的无限穷举。

### W2-004 混合/规则

**实现目标（参考）**

- 新增 `HybridSpec`：
  - 字典 × 固定/掩码前后缀；
  - 最小规则子集（如 lower/upper/capitalize/reverse/append/prepend/duplicate/简单 leet），规则语法和优先级写进任务文档；
  - 规则数量/单 password 长度上限。
- `HybridSource`：
  - 复用 W1 流式字典；对每个 base candidate 生成有限变体；
  - 批次总候选字节受 W1 的 8 MiB/批次约束；
  - checkpoint 记录字典行 + 变体索引/规则指纹，避免重放整段。
- 测试：规则解析错误、去重语义（不做全局去重时明确）、与 mask 组合、已知密码、断点。

**设计目的**

- 大多数真实字典攻击是“词典 + 前后缀/大小写变化”，比纯 mask 更实用；
- 复用 W1 字典流，避免把字典读入内存；
- 不引入 hashcat 规则引擎依赖，保持许可和实现边界可控；
- 为 W2-002/003 提供组合层，而不是再写一套候选生成。

**不做什么**

- 不做 hashcat 全规则集/全兼容；
- 不做跨任务的全局去重（W1 已明确不做）；
- 不做 GPU rule engine。

### W2-005 批量任务/包间复用

**实现目标（参考）**

- 新增任务清单（JSON/TOML 均可，具体实现时定）：
  - 每条：归档路径、攻击模式/字典、线程、checkpoint 目录、可选密码复用开关；
  - 路径/指纹校验；缺文件/坏包单条失败不终止队列。
- `JobRunner`：
  - 串行/有限并行；每个 job 独立 `RunContext`/checkpoint；
  - 失败隔离、汇总退出码、每任务状态（成功/未找到/错误/已停止）；
  - 密码复用只允许在用户显式授权的任务组内，命中密码不写入日志/汇总明文。
- CLI：`--jobs <manifest>`、`--job-output <path>`；`--resume` 对每个 job 生效；
- 测试：100 个小包、单包损坏、单包缺卷、密码复用、暂停/停止、输出不含密码。

**设计目的**

- 真实用户往往有多个归档；逐个手跑 CLI 不可用；
- 批量必须“失败隔离”，不能因为第 3 个包损坏丢掉前面结果；
- 每个任务独立 checkpoint，避免 W1 单任务状态机被多任务污染；
- 密码复用是用户收益点，但必须显式授权并避免日志泄密。

**不做什么**

- 不做 GUI 队列（W3）；
- 不做跨用户/在线共享密码；
- 不做无界并发打开归档（需要会话/句柄上限）。

### W2-006 编码变体与严格模式

**实现目标（参考）**

- 编码层：
  - ZIP：无 UTF-8 标志时 CP437/GBK 候选变体（按归档元数据/用户指定）；
  - RAR4：OEM/UTF-8 候选变体；RAR5 按现有 OEM/Unicode 外部路径；
  - 7z：UTF-8 为主，记录不可转换候选。
- CLI：`--encoding <name>`/`--encoding-variants`（具体拼写实现时定）；
- 严格模式：
  - `--strict`：禁用所有“可能漏报”的快筛，完整验证；
  - `--rar-no-fast-reject`：仅关闭 RAR5 check 快筛，用于差分/排障；
  - 快筛命中/否决计数输出，便于定位。
- 测试：非 ASCII 已知密码、CP437/GBK/OEM 样本、严格 vs 快速结果一致、快筛关闭后无漏报。

**设计目的**

- W1 的 RAR5 快筛只对 ASCII 开启；非 ASCII 仍走外部，性能有限但正确性优先；
- 编码错误会造成“密码明明对却找不到”的假阴性，必须显式建模和差分；
- 严格模式是用户/QA 的可信回退，也是快筛出问题时的排障开关；
- 不把编码猜测藏在快筛里，避免不可解释的漏报。

**不做什么**

- 不做无限编码猜测/在线编码库；
- 不做密码规范化（NFC/NFD）之外的隐式转换而不记录；
- 不改变 RAR5 ADR 的 ASCII-only 边界。

### W2-007 CPU 快筛补全

**实现目标（参考）**

- ZIP：
  - 评估/实现 verifier/结构判据（密码校验字节/加密头/首块 CRC 等），只用于否决；
  - 命中仍由 `zip` crate 完整读取/CRC 复核。
- RAR4：
  - 评估头加密首头校验的可行性；只有评审确认不越过“不解压 RAR”边界才实现；
  - 否则保持外部 `UnRAR t`，不强行做。
- 7z：
  - 复用 W1 头 CRC/首块探测，补 strict/计数器/错误分类；
  - 不因快筛跳过完整 CRC。
- 通用：
  - 快筛只返回“确定错/可能对”；可能对必须完整验证；
  - 解析失败/缺 check/非 ASCII/KDF 超限全部回退；
  - 每个格式记录否决率、误报/漏报差分。
- 测试：错误候选 0 误报、严格模式 0 漏报、RAR4 不解压边界、性能对比。

**设计目的**

- W2-005 批量后外部进程调用会成为瓶颈，快筛能显著降成本；
- 但 RAR 的许可边界比性能更重要：RAR4 没有等价 check 就继续外部；
- 快筛必须“只否决”，不能成为新的命中判定来源；
- 为 W4 的 Full 随包/自动解压保留正确性边界。

**不做什么**

- 不实现 RAR 解压器/压缩器；
- 不链接 unRAR/7-Zip RAR 源码；
- 不做“文件签名启发式”直接判命中。

### W2-008 语料/差分/基准

**实现目标（参考）**

- 语料脚本：生成/索引 ZIP/7z/RAR 负例、分卷/SFX、非 ASCII、1 GB 条目；
- 差分 oracle：ZIP/7z 用内置完整验证，RAR 用外部 `UnRAR t`；记录版本/命令；
- 基准：各攻击模式 1M 级 p/s、CPU、RSS、ETA 误差；同机同电源模式；
- 报告：`docs/benchmarks/W2-*.md`；样本/字典不入库，只记录生成方式/哈希；
- 回归：W1 基准不回退（允许噪声范围，需说明）。

**设计目的**

- W2 的攻击面变大，不能只靠单元测试；必须有可复现的差分/负例/性能证据；
- 语料不入库，避免仓库膨胀/版权/隐私问题；
- 为 W2 退出和 W3 GUI 提供稳定基线；
- 让“快筛/编码/批量”的收益和风险都能被数字验证。

**不做什么**

- 不提交大归档/字典；
- 不用未复现的第三方数字当结论；
- 不把基准 harness 做成产品功能。

## 4. 依赖与顺序

```text
W1 signoff
   │
   ├─ W2-002 mask ──► W2-004 hybrid/rules
   ├─ W2-003 brute ─┘
   ├─ W2-006 encoding/strict ──► W2-007 fast filters
```

建议先做 **W2-002/003**（候选源复用 W1 接口），再做 W2-004/005/006/007，最后 W2-008 收口。W2-006 的编码差分最好在 W2-002/003 前建立最小矩阵，避免后面返工。

## 5. 准出标准（唯一）

> 本节才是 W2 准出依据；§3 的“实现目标”只是参考，不作为验收门槛。

- 掩码/暴力/混合/规则全部可用，已知密码 100%；
- 批量/包间复用/编码变体/严格模式通过语料；
- CPU 快筛 0 误报、严格模式 0 漏报；
- 1M 级基准、p/s/CPU/内存/ETA 记录；无 P0/P1；
- `cargo fmt/clippy/test`、MSRV 1.89、release、cargo-deny、CI 全绿；
- 许可边界不变：RAR 只外部/独立 check，hashcat 不是 Cargo 依赖，GUI 不引入。

# W1-008 正式基准

- **状态**：**完成（1M ZIP / 1M 7z / 1M RAR 均已实测；RAR 约 75 min）**
- **日期**：2026-11-26
- **主机**：Windows 11 build 26300；Intel Core i5-14600K（14C/20T）；31.7 GB RAM
- **工具链**：rustc 1.100.0 `x86_64-pc-windows-gnu`，release profile
- **CLI**：`core/target/release/acx.exe`，`-t 14`
- **基准脚本**：[`scripts/bench-w1.ps1`](../../scripts/bench-w1.ps1)
- **语料**：用户本地 `测试文件/`（不提交）；1.3 GB 测试文件 + 合成 1M 错误字典（15 MB，`wrong-00000000`…）

## 1. 方法

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/bench-w1.ps1 `
  -Archive "测试文件/zip加密.zip" `
  -Dictionary "core/target/w1-008-wrong-1m.txt" `
  -Threads 14 -Label zip-1m `
  -Checkpoint "core/target/w1-008-zip-1m.checkpoint"
```

- 每个格式使用**不在字典中的错误候选**，跑完得到 `NOT FOUND`，避免命中提前结束；
- 记录 wall time、进程 peak working set、进程 CPU time；CPU 百分比按 20 个逻辑处理器归一化；
- 未包含 I/O cache 预热脚本；同一台机器、同一次开机、电源模式为默认高性能（未修改）；
- 不把大语料/字典提交进仓库。

## 2. ZIP AES（1.3 GB，1M 候选）

| 指标 | 值 |
|---|---:|
| 归档 | `zip加密.zip`，AES，条目 1,327,362,712 B |
| 候选 | 1,000,000 个错误候选 |
| 线程 | 14 |
| 退出 | 1（NOT FOUND） |
| wall time | **42.247 s** |
| 吞吐 | **约 23,670 候选/s** |
| peak RSS | **3.1 MB**（父进程） |
| 进程 CPU | 547.906 s |
| CPU 利用率 | 约 12.97 / 20 逻辑处理器（64.8%） |

ZIP AES 的 PBKDF2 是主要成本；1M 错误候选在 42 s 内通过 verifier 拒绝，符合预期。

## 3. 7z AES（1.3 GB，1M 候选）

归档 `新建压缩.7z`（AES，非头加密，条目 1,327,362,712 B）。100k 预跑 173.107 s；1M 全量已完成。

| 指标 | 100k 预跑 | 1M 全量 |
|---|---:|---:|
| wall time | 173.107 s | **1271.049 s（21.18 min）** |
| 吞吐 | 约 578/s | **约 786.8/s** |
| peak RSS | 3.1 MB | **3.1 MB** |
| 进程 CPU | 1,531.391 s | 14,247.375 s |
| CPU 利用率 | 约 8.85 / 20（44.2%） | 约 11.2 / 20（56.0%） |
| 退出 | 1（NOT FOUND） | 1（NOT FOUND） |

1M 候选的实际吞吐高于 100k 预跑，原因是 100k 只有 25 个批次，未完全填满 14 个 worker；1M 有 245 个批次。

## 4. RAR（1.3 GB）

RAR 当前每个候选都要启动一次外部 `UnRAR t` 整包测试。100 个错误候选、14 线程（实际只有 1 个批次，单 worker）为 **5.218 s**，约 **19.2 候选/s**；peak RSS 3.1 MB，父进程 CPU 0.375 s。

1M 全量已完成：

| 指标 | 100 采样（单 worker） | 1M 全量（14 线程） |
|---|---:|---:|
| wall time | 5.218 s | **4515.104 s（75.25 min）** |
| 吞吐 | 约 19.2/s | **约 221.5/s** |
| peak RSS | 3.1 MB（父进程） | **3.1 MB（父进程）** |
| 父进程 CPU | 0.375 s | 4070.797 s |
| 退出 | 1（NOT FOUND） | 1（NOT FOUND） |

RAR 的 CPU 指标只统计 `acx.exe` 父进程；`UnRAR.exe` 子进程 CPU 未计入，因此 wall time 和吞吐是主要指标。


## 5. 结论与 W1 准出影响

- ZIP 1M × 1GB：**实测通过**（42.247 s，23,670/s）。
- 7z 1M × 1GB：**实测通过**（1271.049 s，786.8/s）。
- RAR 1M × 1GB：**实测完成**（4515.104 s，221.5/s，约 75 min）。
- W1-009 的 RAR5 check 快筛将同一 RAR5 1M 降到 **424.838 s / 2353.8/s**（见 [W1-009](W1-009.md)）；W1-008 的 4515 s 仍作为外部整包 oracle 基线保留。
- 三格式 1M × 1GB 的**性能门禁已达到**；RAR 的代价最高，但不再是“未验证”。
- 仍未覆盖：ZIP 10⁷ 错误候选的正式长跑、7z/RAR 的 10⁵ 差分全矩阵、暂停/停止时延矩阵；这些属于 W1 正确性/控制项，不能用本基准替代。
- 本报告不包含密码、字典内容或归档样本；它们保留在用户本地并已 gitignore。

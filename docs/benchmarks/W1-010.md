# W1-010 收口基准

- **日期**：2026-11-26
- **主机**：Windows 11 build 26300；i5-14600K 14C/20T；31.7 GB
- **代码**：W1-009 分支，4096 in-flight 候选窗口
- **补充**：按用户后续指令，ZIP 10M 后停止更大规模/其他格式测试，但继续完成暂停/停止 1 GB 矩阵。

- 归档：1.3 GB `zip加密.zip`（ZIP AES，条目 1,327,362,712 B）

- 结果：`NOT FOUND`，退出 1
- **0 误报 / 0 异常**
- wall：**393.569 s（6.56 min）**
- 吞吐：**25,409 候选/s**
- parent peak RSS：**3.1 MB**
- parent CPU：5443.031 s（约 13.8 / 20 逻辑核）

## 3. 暂停/停止 1 GB 矩阵

使用 [w1_latency](../../core/crates/acx-cli/examples/w1_latency.rs) 驱动真实 scheduler + 1.3 GB 归档（本地 fixture）：

| 格式 | pause 接受 | pause 状态观察 | resume | stop→退出 | outcome |
|---|---:|---:|---:|---:|---|
| ZIP AES | true | <0.001 ms | true | 0.709 ms | Stopped |
| 7z AES | true | <0.001 ms | true | 11.581 ms | Stopped |
| RAR5 + check | true | <0.001 ms | true | 5.545 ms | Stopped |

上表是“错误候选流中暂停/继续/停止”的控制路径；**pause 状态是立即置位**，worker 仍需在候选边界完成当前调用。

“正在验证 1.3 GB 正确候选时 stop”的尾延迟：

| 格式 | stop→join | 结果 | 说明 |
|---|---:|---|---|
| ZIP AES | **1091.804 ms** | Found | 已进入 1.3 GB CRC/HMAC；不能中途抢占 |
| 7z AES | **5036.663 ms** | Found | 已进入 1.3 GB 完整 CRC |
| RAR5 外部 | **5.686 ms** | Stopped | 外部 `UnRAR` 子进程被取消 |

直接单候选（正确密码、1 线程、含启动）：

- ZIP：2.083 s
- 7z：6.020 s
- RAR5：1.368 s

硬杀：14 线程 RAR5 1M 运行 30 s 后 kill，checkpoint `completed_through=58607`、`tried=73537`，重放差 1242 候选（≤4096）。

## 4. 结论

- 控制请求观察 ≤200 ms：**通过**（状态立即置位；worker 边界按 20 ms 轮询）。
- 外部 `UnRAR` 子进程取消 ≤2 s：**通过**（本机 5.686 ms）。
- 1 GB CPU 候选停止尾延迟：**已记录**；ZIP 约 1.09 s、7z 约 5.04 s，不承诺 ≤2 s。
- 硬杀恢复 ≤4096：**通过**（1242）。
- ZIP 10^7 负例达到 W1 正确性门槛：0 误报；
- 1M ZIP/7z/RAR 当前窗口性能均有数据；
- 剩余仅 PR 合并/签核、更广泛第三方 `-hp` 语料、物理核数默认值。
